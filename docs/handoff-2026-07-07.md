## Protocols that bit us this arc (read before starting)

- **Never merge** — merging `main` is a prod deploy. PR + `/code-review`;
  Raphael merges. Chart `version:` bumps only for `charts/warn-v2/` changes,
  re-checked against main just before merge.
- **One-off prod Jobs are w_homelab GitOps**: `clusters/prod/apps/warn-v2/`
  job yaml + kustomization entry; resources on **every** container incl.
  initContainers (CI policy); **no `ttlSecondsAfterFinished`** (Flux
  resurrects reaped Jobs); prune via follow-up PR. The kustomization
  resource list is high-churn when sessions run in parallel — expect a
  rebase, resolve by keeping everyone's entries.
- **Wayback**: CDX content filters are load-bearing (unfiltered prefix
  queries silently truncate at the row limit); url-list mode now paces 3s
  per fetch with a 3-attempt/30s/90s retry, but **completion is verified
  per-record against prod, never by job chunk counts** — throttled drops
  are silent, and top-up re-runs dedupe by `notice_id`.
- **Prod API paging**: `limit<=100` with sleeps. Full-speed paging OOMKilled
  the API once (fixed at 512Mi, but be polite).
- **Tests from a worktree**: sibling venv python (`-m pytest`, cwd first on
  sys.path); the venv may lack newly-merged deps — `uv pip install <pkg>
  --python C:\Users\rapha\workspace\warn_scrapper_v2\.venv\Scripts\python.exe`.
